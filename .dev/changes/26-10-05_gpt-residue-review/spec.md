# 对话残留与断链审查

## 范围

- 当前对话菜单新增「检查残留与断链」。残留定义为 nodes 中存在但从当前 root 沿所有 children 不可达的记录；不按当前 worldLine 或 version 判定。
- 窗口按图外记录的关联组展示，不只列孤立点。关系图区分图外记录、正常树锚点和缺失记录；区分 children 连线与 parent 声明，异常引用有可读解释。
- 显示每组/节点的角色、内容摘要、版本数、模型、已记录时间及估算占用 KB。节点可查看全部版本正文、推理及原始记录；未记录时间不伪造。
- KB 使用序列化节点 JSON 的 UTF-8 字节数 / 1024，包含全部版本及节点附加数据；明确标为估算，不承诺磁盘文件大小或精确释放空间。
- 默认不选中，用户按组审查、勾选；执行前再次显示组数、节点数、估算体积及备份安排。组内节点一起清理，避免选择后留下新的组内断链。
- 清理不触碰任何可见树节点，不自动重连、不恢复分支；可见节点或当前 worldLine 引用的图外组禁止清理，报告原因。root 缺失且存在数据时只检查，不允许删除全部记录冒充修复。
- 删除选中的图外组及对应书签/路径引用；无关的断链和结构异常仅报告，不随意修改。

## 执行与恢复

- 宿主拥有检测和清理规则。iframe 不推算删除范围、不直接写历史。
- 预览只预留独立备份 ID 并显示新文件位置，不写入文件。用户明确点击「保存清理前完整备份」后才写入永久 JSON 历史，标题注明「残留清理前备份」，不覆盖原会话存档；保存后返回审查仍保留此备份。
- 备份与清理是两个明确动作。备份须读回核验完整正文，宿主保留与来源快照绑定的核验凭据，iframe 不可自行授权删除。点击「清理当前工作版」时重新读回备份并复核来源 session、生成状态及完整快照，变化、丢失或读写失败均拒绝清理。
- 清理仅更新当前工作版与缓存，不自动更新原永久存档；用户另行点击「更新永久存档…」，通过独立的覆盖确认后才更新。
- 本地工作副本保存失败恢复原树，备份保留；沿用现有缓存异步同步边界，不增加跨设备事务。
- 列表搜索/勾选/展开/预览不写入历史。真实用户文件仅作只读验证，不自行清理或部署。

## 验收

- 断开的链、其他根、单个幽灵节点、悬空父/子引用和循环可被发现、定位和查看。
- 同一棵树改变 active path 或版本不改变分类；可见树与全部版本清理后保持不变。
- 未勾选、取消确认、过期检查、生成中、备份失败和本地保存失败不导致删除。
- 真实结构案例仍报告图外 1886 条；审查和内存清理不改源文件。
