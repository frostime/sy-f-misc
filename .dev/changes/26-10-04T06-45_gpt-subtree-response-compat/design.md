# 实现设计

## 子树

- 用户评审后选择改为节点 ID 集合，替代界面上的 root/endpoint 持久模式。数据仍是 V2 单根树，不改变历史 schema；保留内部已有 root/endpoint 提取入口作为兼容调用方式。
- `subtree-selection.ts` 是选区连通性、显式连接闭包、可移除/受保护节点的唯一规则 owner。iframe 通过现有 SDK 调用 TreeModel 的分析，不复制一份安全算法。另一种方案是在 iframe 和 host 分别计算规则，会让预览和执行随规则更新发生漂移，因此不采用。
- 按原树的后代到祖先顺序计算保护，不依赖用户点击顺序。选中中间节点仍可复制；与独占部分混选时不再整体拒绝删除，而是在用户明确确认后只移除独占部分。零可移除节点不执行。
- 不连通区域可删除安全部分，但复制/剪切要求一棵连通选区。补齐连接路径是显式选择命令，不是提取副作用；不制造虚拟 root、不重连、不拆分新会话。
- 选择 owner 在 iframe：单击增删一个 ID，菜单修改集合；查看详情与集合选择互斥，单击不同时改变两种含义。保留现有树布局与主题，不将 prototype 代码直接提升为生产实现。
- 删除/剪切使用一次影响图预览和确认；host 在任何保存/删除副作用前重新分析并检查确认计划，防止过期预览删除不同范围。失败返回原选区，不静默缩减后执行。
- 复制与删除使用不同判断：复制只要求所选 children 子图可投影为合法单根树，不要求原始 parent 双向记录全局一致；目标 parent 从所选边重建，不回填原树。
- `getRootedTreeNodes` 定义 root 沿 children 可达的只读树视图，host 传给 iframe 的节点、选区投影、逆索引与删除保护使用同一视图，不读 worldLine 或 versions 决定资格。保护只沿树内 children 传播；图外记录的 parent 声明和 children 列表不能阻挡可见子树。删除只更新可见树的边，图外存储记录原样保留。若移除实际 root 会留下未选存储记录，则保留 root；底层空树覆盖断言仍保留。没有源树重连/压缩或自动历史修复。
- 诊断 DTO 包含 kind/nodeId/relatedNodeIds/可读 message，前端用角色和摘要展示，关联节点虚线高亮并可定位；未显示的存储记录显式标注。ID 收入折叠技术信息。菜单打开与诊断分析分离，异常只能影响相应范围/执行资格，不能使菜单消失。
- TreeModel 一次 batch 删除独占节点，过滤保留节点的 children、worldLine 和书签。受影响的世界线停在保留前缀，不跳到其他分支。
- 剪切先校验并复制全量 version 元数据。UI 通过影响图明确确认一次，host 不再叠加第二个确认框；`subtree-removal.ts` 统一删除/剪切的本地提交与回滚：先成功保存目标对话的本地工作副本，再删除独占节点并保存原会话，最后切换到新会话。失败时恢复原树并保留选择以便调整。
- 删除后立即走已有单会话临时持久化；本地保存失败恢复原树。特别保存被清空的原会话，防止旧缓存复活。`saveToLocalStorage` 增加 boolean 返回值，表示权威本地工作副本是否写入成功；其他调用方的异步副本行为不变，无持久化系统重构。
- 安全边界仍是既有本地工作副本 + 异步同步副本，不新增跨设备/跨会话事务或崩溃恢复日志。目标先保存：中断最多留下两份，不会两边同时消失；若失败后的存储仍拒绝回滚保存，则保留已保存的目标备份以防丢数据。
- 恢复/提取时显式空 system prompt 必须保留，不回退为全局默认 prompt。

### 调查发现：Store 对象不是替换语义

`@frostime/solid-signal-ref` 的 `update` 转发 Solid store setter，其对象赋值是 merge。原 `clear()` 对 `nodes.update({})` 和 `bookmarks.update({})` 的调用实际上没有移除任何 key，`fromHistory` 也会残留旧树。子树提取切换新会话依赖清空/恢复行为，因此本次范围内修正：用 key→undefined 真正移除，并在恢复历史前清空旧 map。离线测试断言无孤儿节点和残留书签。

## 消息版本

- `message-lifecycle.ts` 封装一次回复的版本归属；准备请求时记录目标 msg/version，流式、完成和错误都写入该目标版本。
- rerun 创建全新 payload，不从旧版本继承 usage、思维链、耗时、工具链等生成结果；否则失败的 rerun 会看似消耗了旧版本 token。
- 请求输入 token 表示整个上下文的输入量，不再写进上一条 user 消息的 `token` 字段；完整 usage 只在回复所属版本中保存。author 保留请求准备时的模型，不被等待期间切换的模型覆盖。
- 生成中的节点禁止用户添加、切换、删除版本；普通回复与工具 follow-up 都走显式版本定位的生命周期写入，不依赖此 UI 限制。
- 工具链仍是已有的一条回复/一个 version 内的请求用量求和，不新增全局 agent 统计。共享 usage 改为可选字段后，避免 `undefined += number` 产生 NaN，且不把初始请求的 cache 明细冒充整轮总计：只合计每个请求都上报的计数，缺失则省略；保留每个请求的已报告用量用于原有工具记录。
- 流式回调增加可选的第三参数，传递分开的累计正文/思维链/usage；保留前两个参数以兼容旧调用方。
- `UsageDetails` 仅接收当前或预览版本的 usage。基本计数简洁显示，明细是输入/输出的子集，不重复求和；未报告值与真实 0 区分。

## 验证

离线 Node tests 使用 Vite 已有的 esbuild，并明确使用 browser Solid 单例以验证真实 hook 响应式状态；不新装依赖。协议测试以 mock fetch 边界、真实 SDK 响应形状验证。应用内 iframe 布局、折叠区交互和缓存同步仍需要运行中的思源人工验收。
