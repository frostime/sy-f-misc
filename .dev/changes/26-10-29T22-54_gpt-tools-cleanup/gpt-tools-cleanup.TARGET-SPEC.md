# GPT 工具清理与思源原生工具接入：Target Spec

状态：规划稿。用户授权本轮建立 change、目标与计划，尚未开始源码实施。

## 背景与目标

`src/func/gpt/` 的工具机制始于 2025 年。旧设计用临时变量保存工具结果和规则文档，再将工具消息压缩成 assistant 文本日志。现在默认的 Standard 模式已经持久化原生工具消息，旧机制仍增加提示词、工具数量和运行期状态。

本次方向是清理这些历史机制，并评估通过 MCP 复用思源原生工具。产品仍是 **chat first、agent second**：对话树、回答多版本和当前插件的聊天体验是主体，工具只是一次回答生成过程中可调用的能力。

## 用户已明确的边界

- 保留 tree / multi-version 机制，不为接入 Agent 或 MCP 替换聊天模型。
- 工具开关当前用于控制提供给模型的定义，不在 `ToolExecutor.execute()` 强制检查启用状态。这是用户的刻意设计，不作为本次缺陷修复。
- 可以增加 `read-rule`，作为读取仍有价值的旧 Rule 内容的过渡工具；完整 SKILL 体系后续另行决定。
- 本次先规划清理，并同时考虑 MCP 接入。MCP 若需要新增外部依赖，用户不希望为了接入而接受它。
- 本轮交付是文档和独立技术调查，不是直接实现全部方案。

## 规划目标

以下是本次实施拟达到的结果。删除范围及条件化的 MCP 能力应在进入实现阶段前按本稿审阅；不能把所有早期审查建议都自动纳入本 change。

### 1. 用只读规则读取替代混合变量机制

保留需要继续使用的旧 Rule 正文，模型通过 `read-rule` 读取。规则索引说明可读内容及何时需要它，但不再要求规则先进入普通变量缓存。

清理普通临时变量、工具参数和结果的自动变量缓存，以及 `$VAR_REF` 引用机制。同步清理普通变量管理 UI、旧工具和相关提示，避免留下新会话仍在建议调用但已不可用的入口。不为这些已删除能力另造隐藏记忆或永久结果仓库。

兼容目标是保留旧 Rule 中有用的知识和旧聊天记录的可读性，不是恢复本来就没有持久化的临时变量。是否给旧的 Rule 专用 `ReadVar` 调用保留短期别名，尚未决定；不得借此恢复完整变量系统。

### 2. 精简 Rule 内容

- 随旧变量、伪日志压缩等机制删除的说明，不迁移为新 SKILL。
- 简短的工具用法、枚举和参数约定放进工具或参数描述，避免再读取一篇教程。
- 保留模型不能可靠猜到的思源领域约定，以及现有工具确实需要的专用语法说明。
- “复杂任务交给用户”“单次最多 3–5 个编辑”等旧策略逐项审阅，不能当作模型常识或永久技术限制机械继承。

本次不建设完整 SKILL 安装、发现、激活或管理系统。

### 3. 新生成只使用原生工具消息，不再生成压缩伪日志

拟停止新增 Legacy 工具压缩记录，工具调用及结果按现有 Standard 形态属于对应回答版本。保留旧 Legacy 记录的读取、显示和现有上下文兼容，不批量重写历史文件，也不因打开旧记录而修改它。

这里删除的是“将原生工具消息改写成短 assistant 日志”的机制，不是 UI 折叠，也不是单次输出的分页、范围读取和长度限制。这些能力仍保留。

旧设置 `toolCallMode='legacy'` 对后续新生成的处理方式，在实现前确定并写入设置兼容策略；不能静默删字段后让旧设置重新启用旧生成路径。

### 4. 有条件地接入思源原生 MCP 工具

目标是在支持的思源版本中，将本机内核暴露的工具作为现有工具组的一部分使用。模型、上下文、对话树和回答版本仍由插件管理，不委托整个思源 Agent 管理会话。

MCP 接入必须满足：

- 不新增 MCP npm SDK、CDN 脚本或运行时下载依赖。不能满足时先报告证据和取舍，不自行安装依赖或扩建通用协议客户端。
- 使用现有工具组、工具选择和审批机制；工具来源差异不能扩散到聊天树或主工具循环。
- 工具调用结果保存到启动生成时确定的回答版本，切换版本和分支不串写。历史回放是构建输入，不重新执行历史工具。
- 不支持的宿主版本、认证失败或工具不可用，只影响原生工具能力；普通聊天和现有本地工具不因此失效。
- 明确实际支持的结果类型。不能丢弃图片、资源或结构化错误后冒充调用成功。

当前仅评估本机思源 `/mcp`，不是任意远程 MCP 服务、stdio 进程管理或 OAuth 客户端平台。

## 架构与兼容约束

1. 继续以当前选中的 worldLine 和各节点选中版本构建上下文。不得引入会话级隐藏结果状态来绕过树与版本数据。
2. `message-lifecycle.ts` 已将流式和最终结果绑定到预先创建的版本。复用这条路径，不新建独立 Agent 会话树、调度器或持久任务系统。
3. MCP 不意味着自动继承思源 Agent 的交互审批，也不意味着更改本地 Shell/Python 默认权限。本地工具的信任策略不在本次顺带修改。
4. 规则清理与 MCP 交付解耦。MCP 路线未证实不能阻止独立完成清理，也不能成为提前删除现有领域工具的理由。
5. 聊天持久化层、同步粒度、归档和导出合同保持不变；在涉及历史代码前阅读 `.dev/docs/gpt-chat-history-persistence.md`。

## 验收场景

| 场景 | 预期结果 |
|---|---|
| 模型需要保留的思源专用规则 | 能发现规则并通过 `read-rule` 读取；规则不是可写普通变量 |
| 普通工具返回数据 | 不产生工具结果变量、缓存引用或提示读取旧变量的额外日志 |
| 新生成包含多个工具往返 | 保存原生消息和必要调用元数据；UI 仍可折叠展示 |
| 打开旧 Legacy 会话 | 原内容仍可读、可继续聊天，不触发历史批量改写或虚构变量恢复 |
| 同一回答 rerun 得到 v2 | v1 的工具消息不被 v2 覆盖；后续输入只展开当前选中的版本 |
| 从历史节点分支 | 上下文遵守原有分支、版本、窗口和 pin 规则，不依赖别的分支的临时变量 |
| 支持的本机 MCP 工具可用 | 能经现有工具组选择、审批、执行，结果进入正确回答版本 |
| MCP 不可用或返回错误 | 有明确的能力失败结果；普通聊天和本地工具仍可用；不自动重试写操作 |
| MCP 返回首版未支持的内容类型 | 明确告知限制，而不是静默丢内容后报告完整成功 |

## 不属于本次自动授权的工作

- 将关闭工具改为执行禁止；完整重做权限策略；提高 Shell/Python 默认审批等级。
- 整体替换 Provider、聊天树、历史持久化或现有思源工具。
- 建设完整 SKILL 生态、永久 artifact 仓库、工作流或自主子代理系统。
- 顺带修复早期审查发现的全部问题。隐私跨轮、中断、部分成功、块编辑等问题见 PLAN 的待定范围项，只有成为本次改动的必要依赖或用户另行确认时才实施。

## 实现前仍须关闭的问题

- 本机思源实际版本、认证方式及 MCP 初始化/响应方式是否允许足够轻量的零依赖实现。
- 首版 MCP 工具与返回内容范围、默认审批映射、名称冲突处理，以及是否开放具有 SKILL 管理副作用的原生 `skill` 工具。
- 停止 Legacy 新生成后的旧设置兼容方式，以及是否确实需要 Rule 专用的 `ReadVar` 过渡别名。

技术证据和候选方案见同目录 `gpt-tools-cleanup.METHOD.md`；阶段与执行状态见 `gpt-tools-cleanup.PLAN.md`。
