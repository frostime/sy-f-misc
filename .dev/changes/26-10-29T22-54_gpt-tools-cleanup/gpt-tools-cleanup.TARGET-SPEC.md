# GPT 工具清理与思源原生工具接入：Target Spec

本文件定义目标、验收和边界；实施状态在 PLAN，技术路线与证据在 METHOD，已接受的架构与 diff 预测在 SHAPE。清理和 MCP 首版均已获实施授权；源码/自动验证与宿主体验验收分别记录，不能混为完成。

## 目标与定位

旧 GPT 工具机制把规则文档、临时变量和工具结果混存，并用 assistant 伪日志压缩调用过程。本次清理这些历史机制，降低提示词与隐藏状态的维护成本；同时评估复用思源原生工具。

产品保持 **chat first、agent second**。tree / multi-version 是聊天功能的核心，不为接入 MCP 或 Agent 替换会话模型。

## 清理结果

### 规则只读，普通变量机制退出

模型用 `read-rule` 读取仍有价值的旧 Rule，不再经普通变量系统读写。索引说明可读文档及适用场景；不保留 `ReadVar` 别名，不恢复本来就未持久化的临时变量。

删除普通临时变量、工具参数/结果缓存、`$VAR_REF` 展开及其管理 UI、工具和提示。不另造隐藏记忆或永久结果仓库。脚本普通 JSON 参数注入、工具分页、范围读取和输出长度限制保留。

Rule 中的通用教程与重复参数说明删除；短约定放工具/参数描述。保留思源领域知识和 diff/slice 等插件专用协议。本次不建设完整 SKILL 发现、安装、激活或管理系统。旧批量数量和复杂任务策略本轮保留，后续单独审阅，不能伪装成执行器技术上限。

### 新生成保留原生消息，旧历史继续读取

新回答的调用与结果使用原生工具消息，属于启动生成时确定的回答版本，不再生成 Legacy 压缩伪日志。UI 折叠不受影响。

旧 Legacy 记录仍可显示、构建上下文、继续聊天和导出；不批量重写历史，也不在打开记录时迁移正文。删除旧生成模式设置，不让旧值重新启用已移除的路径。具体配置迁移方式见 METHOD。

## MCP 接入范围

在满足约束的思源宿主中，通过原生工具复用能力；插件继续管理模型、上下文、聊天树及回答版本，不委托整个思源 Agent 管理会话。

接受的接入必须：

- 不新增 MCP npm SDK、CDN 脚本或运行时下载依赖。需要这些依赖时先回到用户决定，不自行安装或扩建通用客户端。
- 与现有工具组、工具选择和审批机制结合，来源差异不扩散到聊天树和主工具循环。
- 官方暴露限制继续有效；插件局部选择与官方全局暴露区分，不能冒充只读安全边界。
- 不可用宿主、认证失败或原生工具故障只影响该能力，不使普通聊天或本地工具失效。
- 明确支持的结果类型；不能丢弃图片、资源或结构化错误后报告完整成功，不自动重发结果未知的写调用。

工具规模与官方控制调查已完成。用户本轮选择独立原生 MCP 工具组：组默认关闭，按整工具选择，首次打开及后续新增工具均默认不选，不因发现成功而全量注入。默认执行策略为每次执行前确认；成功结果默认直接发送给模型，保留现有单工具权限覆盖。

用户审阅 SHAPE 及独立评审处置后回复“方案大致 Ok，请开始”。首版采用 GPT 启动时一次发现，5 秒内就绪或仅原生组不可用；不热更新、不自动重连或重发。工具以 `sy_mcp_<原名>` 注册，保留文本与结构化 JSON，未支持内容明确报告结果不完整和操作可能已执行。只支持当前 Provider 可无损表示的输入定义，不剥除约束后虚报支持。

协议连接与定义属于本次 GPT 启动，选择与审批属于各 executor。旧组件不自动换绑重启后的连接；必须重开标签页/窗口，旧标签内“新建对话”仍复用 executor。原生 skill 仅作可选工具，不自动导入原生 Agent 工作流；首版不加入免审批的 Tool Hub。直接相交的权限页修复纳入本轮：修改一种审批不得意外更改另一种有效策略。

后续涉及用户可观察行为或代码架构的实质变化，仍须先讨论；实施授权不包含扩大依赖、通用客户端、权限系统或聊天存储的范围。

当前只考虑本机思源 `/mcp`。任意远程服务、stdio 进程管理、OAuth 客户端平台及原生 Agent session 映射不属于本次默认范围。

## 不可破坏的合同

1. 按当前 worldLine、窗口/pin 和选中版本构建上下文。历史回放不重新执行工具，也不依赖别的分支的临时结果。
2. 流式及最终结果写入预先创建的版本，不写用户后来切换到的版本。复用现有生命周期，不另建 Agent 会话树、调度器或任务持久化系统。
3. **工具开关只控制提供给模型的定义，不在 `ToolExecutor.execute()` 强制禁止按名称执行。** 用户刻意保留此语义；它与官方服务端暴露限制是不同层次。
4. MCP 不自动继承思源 Agent 的审批交互。本轮不顺带改变 Shell/Python 默认信任策略，也不宣称旧审批/中断缺陷已全部修复。
5. 清理与 MCP 解耦；MCP 暂停不回滚清理，也不成为提前删除现有思源领域工具的理由。
6. 聊天存储、同步粒度、归档和导出合同不变。涉及该区域前读 `.dev/docs/gpt-chat-history-persistence.md`；共享 VFS 与自定义脚本执行/格式化/权限能力不得被死代码清理误删。

## 验收与验证责任

| 场景 | 正向/负向判据 |
|---|---|
| 读取规则 | 索引可发现，`read-rule` 完整返回已注册文档；未知名称明确失败，不能写入规则 |
| 普通工具及结果拒发 | 无参数/结果变量、缓存引用和伪系统日志；拒发成功结果不能经旧变量入口取回 |
| 新生成多轮调用 | 保留原生 assistant/tool 序列与最终文本，UI 可折叠，不用伪日志替代调用 |
| 旧 Legacy 记录 | 可显示、续聊、导出；不重写旧 payload 或虚构失效缓存 |
| rerun、切版本、分支 | 旧版本不被覆盖，新生成仍写启动版本；后续上下文遵守选中路径及版本 |
| 原生 MCP 工具 | 经选定的组/工具选择、审批、执行及结果转换，进入正确回答版本 |
| MCP 故障或未支持结果 | 明确告知限制；普通聊天可用，不静默丢内容、虚报成功或自动重发未知写入 |

Agent 负责源码核对、自动测试、构建、可控运行探针及失败归因，并明确未验证范围。用户确认真实思源交互、存量会话体验及产品取舍；自动测试不代替用户验收。具体命令、基线阻碍及未完检查在 PLAN。

## 尚未验证的宿主边界

- 已加载候选构建的完整插件 UI、真实 Provider 请求与交互审批、旧会话体验仍需宿主验收。隔离浏览器中的生产 client/桥接/executor 通路不代替这些证据。
- 当前运行证据限 dev 3.8.8。带认证实例、独立窗口和较旧宿主未因此取得支持证明，不顺手提高最低宿主版本或扩建兼容平台。

早期审查的其他缺陷只作为 METHOD 的后续范围记录；若阻塞本次接受的合同，先明确纳入范围再处理，不借清理重做整个 Agent。
