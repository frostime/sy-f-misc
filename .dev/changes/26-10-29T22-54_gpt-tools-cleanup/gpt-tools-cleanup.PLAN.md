## Current Phase

### 目标与边界

当前先解决 [I6] 的运行不确定性和 [I11] 的工具规模/控制问题，不直接实现完整桥接，也不预先增加新的开关抽象层。MCP 不可用不得导致普通聊天失败，也不得接管插件的对话树。思源源码里的 JSONResponse、认证回退和双协议分支只是候选路线依据，不是本机保证。

先确认目标思源实例与版本，在已授权的同源认证上下文执行最小探针：初始化/协商、工具列表、一个选定的只读调用。记录协议/session header、HTTP 状态、结果形态及角色限制，同时统计工具数、各工具 action 数和 JSON 定义体积。不要读取用户 token/config、笔记正文或执行写工具来替代协议验证。

探针成立后，展示实际工具清单，关闭 [I7] 的工具范围、命名、结果类型和默认审批选择，再实现一条原生工具组纵向切片。若需要 OAuth 平台、通用 SSE/stdio 兼容、外部 SDK 或明显提高宿主版本下限，带证据回到用户决定，不追加 fallback 或重连框架。

### 并行边界与验证责任

清理阶段的规则、设置和元数据由三个受限 worker 分别处理，主代理完成执行器、工具链、原生结果转换及测试，并回查整合结果；独立 reviewer 的四项提示已核对，补回文件编辑参数说明并移除死导入/导出。所有源码变更已结束，后续并行任务必须重新约定文件所有权。

MCP 探针可以与 [I8] 的清理宿主手测独立进行，但两者结果不可互相替代。主代理承担源码、自动回归与最终综合；用户需要验证真实思源交互。

### 出口与当前位置

出口：只读探针取得可复查运行证据，明确可以承担的有限协议范围，且工具/结果/审批选择已确定；不满足时明确记录暂停原因，不自动开始桥接。

Now：清理代码已提交，尚未实施 MCP。[I11] 已确认官方三种控制的作用及整工具暴露粒度，但本项目 CLI 的 dev 实例校验失败，需要用户确认/启动目标实例后才能采集实际清单。没有绕过校验继续访问其他实例。接着完成 [I6]/[I11] 或 [I8] 手测；不要重新建立变量仓库或宣称浏览器回归已通过。
