## 真实接口链测试的范围

`tests/run-gpt-archive-tests.mjs` 运行真实 json-files.ts、archive-actions.ts、residue-cleanup.ts 和 storage-read.ts；模拟平台 VFS 写入、思源 API 读取/目录、插件索引保存、确认 UI 和剪贴板。并未把 saveBackup 模拟成永远能正确返回成功/失败。

- VFS 返回 ok:false 时永久保存拒绝，索引不发布，不能生成核验凭据或清理。
- 正文已写但索引失败时明确报部分失败，不生成清理凭据；已写正文不删除。
- 取消/关闭确认、目录读取失败均零正文写入；明确确认后只覆盖选定文件，其他存档不变。
- 新建也须用户确认；确认期间原存档正文改变会拒绝覆盖。
- 复制链接零正文/索引写入；无永久档不生成链接，已存在时使用永久标题。

单元测试另保护：备份读回缺失/损坏、清理前备份被删、来源在异步重读时变化、生成/会话切换、清理本地保存失败恢复。UI 归档覆盖确认的内容/取消在模拟 DOM 中测试，尚未在思源原生 Dialog 内验收。

## 思源内建议验收

使用虚构会话，不直接清理真实历史：

1. 完整更新 dist/ 后重载插件，重新打开聊天及审查窗口。旧窗口不作为新代码验收依据。
2. 新会话选择建立永久存档，检查新建目标路径、数量及按钮；取消不生成文件。确认后历史列表存在完整 JSON。
3. 修改工作版，选择更新永久存档；核对原/当前数量、整体覆盖说明；确认框不展开或渲染原正文。关闭/取消后永久档未变，确认后重开存档核对全部分支/版本。
4. 未归档时复制存档链接只提示先归档；已归档时修改工作版再复制，链接仍打开永久版，不发生保存。
5. 导出工作版到笔记/附件，核对 chat-history 文件未因此新建或更新；原导出目标仍按既有行为创建/更新。
6. 残留窗口预览显示备份名称及新路径；点击保存备份后检查实际新 JSON、全部原数据及版本，同时当前工作版仍未变化。返回审查，备份仍在。
7. 单独清理后仅缓存变化，原永久文件仍旧；按可选更新永久存档并确认后才替换，完整独立备份继续保留。
8. 保存备份后在主聊天切换版本/编辑内容/切换会话或启动生成，清理应拒绝，重新检查后才允许重新备份操作。
9. 临时历史多项归档逐项确认；中途取消后只已完成项目取消勾选，未处理项目仍在，缓存不删除。
10. 检查深色/窄窗口、大存档确认框不渲染全文，以及实际文件 I/O 故障提示。不要仅凭成功列表条目判定备份存在。
